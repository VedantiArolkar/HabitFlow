# HabitFlow — Smart Habit Tracker

A full-stack habit-tracking web application built with **Java 21, Spring Boot 3, Spring JDBC (`JdbcTemplate`), MySQL 8, Spring Security, Thymeleaf, JavaScript, Bootstrap 5, and Chart.js**.

HabitFlow helps users build consistent routines, track daily completions, set goals, and understand their progress through dashboards, analytics, a calendar, and rule-based insights. Metrics are calculated from application data stored in MySQL rather than hardcoded dashboard statistics.

**Repository:** `https://github.com/VedantiArolkar/HabitFlow`

## Highlights

- **Account management:** registration, login, logout, profile updates, and password changes.
- **Habit management:** create, edit, archive, reactivate, and delete habits; configure categories, frequency, weekdays, reminders, icons, and colours.
- **Daily tracking:** mark a habit complete for a date, undo a completion, and optionally add a note.
- **Streak calculations:** current and longest streaks, total completions, and consistency rates.
- **Goals:** create goals, link habits, track progress, and receive milestone messages.
- **Analytics dashboard:** daily, weekly, and monthly rates, trends, category performance, a heatmap, and per-habit statistics.
- **Calendar:** review completed, partially completed, missed, and unscheduled days.
- **Insights:** explainable, rule-based recommendations generated by Java logic; no external AI service is called.
- **Notifications:** in-app completion, goal milestone, reminder, and weekly-summary notifications.
- **REST API:** JSON endpoints for the application's core features.
- **Automated tests:** unit tests for selected business logic, with an H2 test database profile.

## How the application works

HabitFlow uses a layered Spring Boot architecture:

1. The browser opens a page route; a controller returns a Thymeleaf page shell.
2. Front-end JavaScript calls the `/api/**` endpoints using `fetch()` and receives JSON.
3. REST controllers validate requests and pass work to service classes.
4. Services apply business rules and transaction boundaries.
5. Repository classes execute SQL through `JdbcTemplate`.
6. MySQL stores users, habits, schedules, completions, goals, and notifications.
7. The UI renders the returned data and charts.

**Design choice:** the application uses Spring JDBC and hand-written, parameterised SQL rather than Spring Data JPA or Hibernate. Controllers handle HTTP requests; services contain business rules; repositories handle database queries.

### Main layers

- **Controllers:** authentication, habits, completions, dashboard, analytics, goals, insights, notifications, profile, and page routes.
- **Services:** application rules, streak calculations, metrics, goals, and notifications.
- **Repositories:** SQL queries using `JdbcTemplate`.
- **DTOs and validation:** request/response objects and input validation.
- **Security:** user identity, session authentication, CSRF handling, and access control.

## Database design

The schema defines these main tables:

| Table | Purpose |
|---|---|
| `users` | User accounts and profile information |
| `habit_categories` | Global and user-owned categories |
| `habits` | Habit details, frequency, targets, and status |
| `habit_schedules` | Weekdays on which each habit is scheduled |
| `habit_completions` | Completion history and optional notes |
| `goals` | Goal targets, progress, dates, and status |
| `goal_habits` | Links goals to habits |
| `notifications` | In-app notifications and read status |

The database schema is available at `database/schema.sql`. The application also includes `src/main/resources/db/schema.sql` for schema initialisation on startup.

### Streak and consistency rules

- A habit is scheduled only on configured weekdays and on or after its start date.
- Unscheduled days are skipped; they are not counted as missed.
- The current streak checks scheduled days and does not penalise an incomplete habit partway through the current day.
- Consistency is calculated from completions on scheduled days over the selected period.
- A unique database constraint on `(habit_id, completion_date)` prevents duplicate completion records.

## Security

- Passwords are stored as BCrypt hashes; raw passwords are not stored in the database.
- Session-based authentication protects private application pages and API routes.
- CSRF protection is used for state-changing requests.
- Repository queries scope data to the authenticated user.
- SQL uses parameter placeholders through `JdbcTemplate` rather than concatenating user input.
- Database credentials can be supplied through environment variables.

**Before deploying:** set a strong database password and keep credentials out of source control. The local defaults in `application.properties` are for development convenience and should not be used as production secrets.

## Run locally on Windows

### Prerequisites

Install the following before starting:

- JDK 21
- MySQL Server 8
- Maven (or use the Maven wrapper if one is included in your checkout)
- An IDE such as Eclipse, IntelliJ IDEA, or VS Code is optional

### 1. Get the project

```bash
git clone https://github.com/VedantiArolkar/HabitFlow.git
cd HabitFlow
```

If you have already downloaded the project, open a terminal in the folder that contains `pom.xml`.

### 2. Check Java and Maven

```bash
java -version
mvn -version
```

Confirm Java reports version 21 and Maven is available.

### 3. Create the database

Start the MySQL service. Then open MySQL Workbench, or use a MySQL command-line client, and execute:

```text
database/schema.sql
```

This script creates the `habitflow_db` database and its tables. If you use a different database name, update the JDBC URL accordingly.

### 4. Configure database credentials

The default connection settings are defined in `src/main/resources/application.properties`. They use environment variables when provided:

```properties
spring.datasource.url=${HABITFLOW_DB_URL:jdbc:mysql://localhost:3306/habitflow_db?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true}
spring.datasource.username=${HABITFLOW_DB_USER:root}
spring.datasource.password=${HABITFLOW_DB_PASSWORD:root}
```

Set the variables to match your local MySQL setup. In Windows Command Prompt, for the current terminal session:

```bat
set HABITFLOW_DB_USER=root
set HABITFLOW_DB_PASSWORD=YOUR_MYSQL_PASSWORD
```

Replace `YOUR_MYSQL_PASSWORD` with your own MySQL password. Do not commit real credentials to GitHub. If you use `setx` instead, open a new terminal or restart the application after setting the variables.

### 5. Build the project

From the directory containing `pom.xml`, run:

```bash
mvn clean package
```

### 6. Start the application

```bash
mvn spring-boot:run
```

Wait for the Spring Boot log to confirm that the embedded Tomcat server has started on port `8080`.

### 7. Open HabitFlow

Visit:

**http://localhost:8080**

Register a new account or use the demo account if demo seeding is enabled.

### Import into Eclipse (optional)

1. Open Eclipse.
2. Select **File → Import → Maven → Existing Maven Projects**.
3. Select the project root folder containing `pom.xml`.
4. Finish the import, then right-click the project and choose **Maven → Update Project**.
5. Run `HabitFlowApplication.java` as a Java application.

## REST API and Postman

The API base URL is:

```text
http://localhost:8080
```

Most `/api/**` endpoints require an authenticated session. State-changing requests also require the CSRF token header `X-XSRF-TOKEN`.

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/api/auth/register` | Register a user |
| `POST` | `/api/auth/login` | Log in |
| `POST` | `/api/auth/logout` | Log out |
| `GET` | `/api/auth/me` | Get the current user |
| `GET`, `POST` | `/api/habits` | List or create habits |
| `GET`, `PUT`, `DELETE` | `/api/habits/{id}` | Read, update, or delete a habit |
| `GET` | `/api/tracking?date=YYYY-MM-DD` | Get tracking data for a date |
| `POST` | `/api/habits/{habitId}/complete` | Record a completion |
| `GET` | `/api/dashboard` | Get dashboard metrics |
| `GET` | `/api/analytics?from=&to=&habitId=` | Get analytics data |
| `GET`, `POST` | `/api/goals` | List or create goals |
| `GET` | `/api/insights` | Get rule-based insights |

The complete API collection is available at `docs/postman/HabitFlow.postman_collection.json`.

To try it:

1. Open Postman and import the collection JSON file.
2. Run the authentication login request first.
3. Use the authenticated session and CSRF token captured by the collection for protected requests.
4. Review each request's description for its expected response.

## Troubleshooting

| Problem | What to check |
|---|---|
| MySQL connection or access denied error | Confirm MySQL is running and the username/password match your local setup. |
| `Unknown database 'habitflow_db'` | Execute `database/schema.sql` or correct the configured database name. |
| Port `8080` is already in use | Stop the process using the port or configure another server port. |
| API returns `401` | Sign in again; the session may have expired. |
| POST request returns `403` | Include a valid `X-XSRF-TOKEN` CSRF header. |
| Eclipse reports Java release 21 is unsupported | Set Eclipse and Maven to use JDK 21, then update the Maven project. |
| A table does not exist | Check application startup logs for schema initialisation errors and execute `database/schema.sql`. |
